Basic Structure of C Program:

Introduction:

The structure of a C program is the way the components are arranged making it easier to read and understand. C programs often consist of preprocessor directives, declarations, a main() function and user defined functions. These are arranged depending on how they need to be for the specific program. A good structure will make the program easier to develop, debug and maintain.
In the basic structure of a C program, the main() function is the only mandatory component required for a program to compile and run.

There are totally 6 sections:

  1. Documentation Section.
  2. Preprocessor Section.
  3. Definition Section.
  4. Global Declaration Section.
  5. Main Function.
  6. Subprogram (User-Defined Function).

Example:

This is a simple code to calculate the area of circle.

              

        /* =========================================================
        1. DOCUMENTATION SECTION
        Description: Calculates the area of a circle.
        Author: XYZ
        ========================================================= */



        // 2. PREPROCESSOR SECTION
        #include  

        // 3. DEFINITION SECTION
        #define PI 3.14 

        // 4. GLOBAL DECLARATION SECTION
        float calculate_Area(float radius);

        // 5. MAIN FUNCTION SECTION (Mandatory entry point)
        int main()
        {
            float radius = 5.0;
            float area;
            
            area = calculate_Area(radius);

            printf("The area of the circle is: %.2f\n", area);
            
            return 0;
        }

        /* =========================================================
        6. SUBPROGRAM SECTION (User-defined functions)
        ========================================================= */
        float calculateArea(float radius)
        {
            return PI * radius * radius;
        }

Documentation Section:

Definition:

A C program will have a section called document. This goes at the top of your source file and contains comments that give information about your program. Although the C compiler ignores this section, it's important to include it so the humans who will be reading, developing and maintaining your code understand what the code does.

What are the things to include in the documentation section?

            A complete enterprise-grade documentation section is broken down into four core logical pillars:
                • Identity & Ownership: Strict metadata defining the file name, author, department, and legal copyright boundaries.
                • Functional Mechanics: Clear, high-level technical documentation explaining what the code does, its dependencies, hardware limitations, and operational complexity.
                • Auditing & History: A clear changelog tracking versions, dates, developer handles, and bug tracking IDs (e.g., Jira ticket numbers).
                • Lifecycle Status: Explicit tags indicating if the code is deprecated, experimental, or thread-safe.

Example:

A simple documentation using multi-line comments.

            
            /* 
            * Title: Matrix Multiplication
            * Author: Jane Doe
            * Date: November 9, 2026
            * Description: This program takes two 3x3 matrices from the user, 
            *              multiplies them, and displays the result.
            * Version: 1.0
            */

            #include 

            int main() {
                // Program logic goes here
                return 0;
            }

A Simple documentation using single-line comments.

            
            // Title: Hello World Program
            // Author: John Smith
            // Date: November 9, 2026
            // Description: A simple program to print 'Hello, World!' to the console.

            #include 

            int main() {
                printf("Hello, World!");
                return 0;
            }

Preprocessor Section:

Definition:

Link / Preprocessor Section is the 1st working part of your C program. It prepares your code for compilation by using external utilities and libraries. Prior to the computer translating your C code into an executable, your file will be scanned top to bottom by a special tool called the Preprocessor. The Preprocessor looks for the Preprocessor Section and runs instructions which begin with a hash (#).

The Anatomy of the Preprocessor Section:

In your code, the section looks like this: 

#include <stdio.h>

This single line consists of two crucial parts:
1. The #include Directive:
This is a direct command to the preprocessor that means, "Go find an external file, copy its entire contents, and paste them right here into my code before compiling."
2. The Header File (<stdio.h>):
This stands for Standard Input Output. It is a built-in system file that acts like a dictionary containing the blueprints for basic commands like printf() (used to print text to the screen) and scanf() (used to read user input from the keyboard).

Common Header Files You Will See in This Section

            Depending on what your program needs to do, you will add different toolboxes to this section:
                • #include <stdio.h>> → For standard input/output (printf, scanf).
                • #include <math.h> → For advanced math operations (square roots, powers, trigonometry).
                • #include <string.h> → For manipulating text strings (copying, joining, or comparing text).
                • #include <stdlib.h> → For memory allocation, random numbers, and process control.

Definition Section:

Definition Section In C Programming, the Definition Section defines symbolic constants and macro expansions with the use of define directive. Although it uses preprocessor directives, this section has its own unique stage following header file includes (#include). Its main purpose is to assign descriptive names to constant values or small pieces of code to make the program more readable, maintainable and editable.

Core Components of the Definition Section

            This section defines macros.
            
            1.Symbolic Constants (Object-like Macros)
                •Rather than having hard coded values (magic numbers), we can define a symbolic constant here. 
                •The pre-processor will search through our source code and replace the macro name with the defined value.
                • Syntax: #define CONSTANT_NAME value
                • Example: #define PI 3.14

            2. Macro Definitions (Function-like Macros)
                •Short single-line pseudo functions can be defined which accept arguments. 
                •There is no overhead of real function calls as they are expanded inline by the preprocessor.
                • Syntax: #define MACRO_NAME(arguments) (expression)
                • Example: #define SQUARE(x) ((x) * (x))

Why do we need Definition Section?

Imagine a program consisting of 5000 lines of code. You have had to type in the tax rate (0.18) many times (say 180 times). Changing it to 0.22 is going to be a nightmare. By using #define TAX_RATE 0.18 in the Definition Section you just have to change it once at the beginning of your code.

Global Declaration Section:

Definition:

The Global Declaration Section comes directly after the Definition Section and before the main() function. This is where you can declare any variables and functions which will be used in various sections of your program. File scope is given to any variables or function prototypes declared here, meaning that they will be available and accessible to all functions below them in the file.

Core Components of the Global Declaration Section

            There are two key things to remember here.

            1.Global Variables:
            
                Variables declared outside of any function.
                They stay in the computers memory throughout the whole running of the program.
                They also have a default value. 
                Unlike local variables which will be filled with random garbage if not initialised, 
                global ints and floats get initialised to 0 by the compiler.
                
            2.Function Prototypes (Declarations):

                Function prototypes tell the compiler that there will be a function, 
                what it will return and what arguments it will take.
                C is a top-down language, meaning that if you try to call a function in main() 
                that is at the bottom of the file you will get a warning/error. 
                By declaring the function in the Global Declaration Section this problem will be solved.

The Risk of Global Variables:

Whilst the Global Declaration Section is an extremely useful tool, generally software engineers will try to avoid using global variables as they have the following issues:

Debugging can become more difficult as any function can change the variable and therefore if it suddenly becomes corrupt it is difficult to tell which function is causing the issue.
Global variables can cause Concurrency Issues if you have an advanced program that has multiple tasks running at the same time (multi-threading).
They take up memory as they are stored from when the program starts until the program ends. Whereas local variables will be cleared once the function has finished.

Main Function:

Definition:

The Main Function Section is the absolute heart of every C program. It is the designated entry point where the operating system hands over control to your code, and where execution officially begins.
No matter how large your program is—whether it has ten lines of code or ten million— the computer will always search for int main() first and start executing instructions

Standard Syntax 

    A simple program:

        int main(void) 
        {
            // Local Declarations 
            int year=2009;

            // Executable Statements 
            printf("Hello World\n");

            // Return Statement
            return 0; 
        }

Let’s break down the syntax:

• int: This lets the OS know that once the program has finished executing, an integer will be returned back to it.

• main: This is a keyword that needs to be written exactly as shown with lower case letters. The compiler is looking for this name.

• (void) / (): This means that this function won’t take any inputs / arguments from the command line.

• { }: These are the start and end of the program.

• return 0;: This returns 0 back to the operating system. This will tell it that everything went fine with no crashes or errors. Any number which isn’t 0 (eg. 1/-1) will generally indicate there was an error.

Internal Structure of Main

The code written inside your main() function would generally consist of two parts:

1. Variable declaration section: This part would contain the declaration of all variables that are only required inside your main() function. These variables would not be accessible to any external sub-function.

2. Execution Section: This section would include the looping, if/else statements, mathematical statements and function calls to other user defined functions.

Another Variation of main Function

While int main(void) is standard for basic programs, C allows the main function to accept inputs directly from the terminal when the program is launched.
This is written as: 

        int main(int argc, char *argv[]) 
        {
            printf("Hello Worlds");
            return 0;
        }

• argc (Argument Count): Counts how many items the user typed when running the program.

• argv (Argument Vector): An array of strings containing the actual text typed by the user.

Note:
• The names argc and argv can be changed as you wish but you should not change anything else (their data type or position).

• Exactly One main: You can only have one main function in an entire project. If you have two, the compiler will get confused and throw a "redefinition of main" error.

• Implicit Return: In modern C standards (C99 and later), if you accidentally forget to write return 0; at the end of main, the compiler will automatically insert it for you behind the scenes. However, it is still best practice to write it explicitly.

Sub Program (User-Defined Functions):

Definition:

The last section of a C program is called the Subprogram Section (or User-Defined Function Section). This section is right at the bottom of your source code file, just below the main() function.
This section contains the actual definitions of all the functions you have declared above in the Global Declaration Section.

Structure of a Subprogram:

Each user defined function has two sections:

Function Header: This declares what type of value the function will return, a unique name and parameters (inputs).

Function Body: This is the part inside the curly braces { ... } which carries out some actions and may return a value.

Syntax: 

        return_type function_name(parameter_list) 
        {
            printf("Iam inside the function.");    
        }

Why put it here?

Having your subprograms actual code at the bottom of your document has two key benefits:

Keeping your code clean and easy to read. When someone opens your file they can easily see what your main() function is doing by having it at the top of your code.
Allows you to create complex programs by splitting a large problem into smaller pieces of code.

Things to Note:

1. Variables declared within a subprogram (e.g. float result) will be local variables. This means that the main() function will not be able to see them. Once the function has finished running they will be deleted from the computers RAM.
2. The function header will need to exactly match what you had in your Global Declaration Section. If the data types or amount of parameters don’t match then you will get an error from the compiler.
